# 衡准 · 物理评分台

高中物理手写作答辅助批改首版。系统默认采用视觉教师模型直批：教师模型直接查看题目、评分标准和学生答卷原图，返回最终答案判定、逐点过程审验和可定位证据；后端负责结构校验、确定性计分、教师评语和风险复核。

## 启动

```powershell
npm install
npm run dev
```

前端默认运行在 `http://localhost:5173`，API 默认运行在 `http://localhost:8788`。

## Windows 用户端

项目提供 Electron 用户端：左侧加载评分控制台，右侧加载独立的内嵌改卷网页。服务端首次启动时会自动保存一份内置、锁定的“模拟网页改卷演练 · 圆周运动”模板。

本地测试站有两个入口：`/mock-grading` 是通用 `data-grading-*` 控件测试页；`/zhixue-mock` 是智学网专用适配器模拟页，复刻 `#topicImgContent`、`.scorearea`、`#txt_marking_all`、`#bnt_save`、`a[title="上一份"]` 和 `a[title="下一份"]` 等真实结构。模拟页提供 JSON 测试用例导入/导出、答卷图像、最终总分保存、自动提交开关、上一份/下一份和任务量进度，不连接真实智学网。

JSON 测试用例格式如下，`imageDataUrl` 可选；没有图片时会根据 `lines` 生成本地 SVG 答卷图：

```json
{
  "version": 1,
  "site": "zhixue-mock",
  "cases": [
    {
      "id": "student-001",
      "studentId": "学生 001",
      "label": "学生 001",
      "questionLabel": "第 16 题 · 竖直圆轨道综合题",
      "maxScore": 18,
      "lines": ["mgR = 1/2mv²", "N - mg = mv² / R", "N = 3mg"]
    }
  ]
}
```

Electron 流水线的“测试任务”默认打开 `/zhixue-mock`，因此可以直接验证智学网专用适配器的页面检查、图像提取、总分写入、提交确认和翻页逻辑；原 `/mock-grading` 入口仍保留用于通用适配器回归测试。

Electron 目标页适配器会从网页的 `img.currentSrc`、`src`、`srcset`、`data-src`、`data-original`、CSS `background-image` 或 `canvas` 中提取学生作答图片，必要时将 SVG 转换为 PNG，计算图片 SHA-256 后调用 `/api/pipeline/grade`。教师模型返回批改结果后，适配器才向网页评分框写入数字、点击提交并进入下一份；服务端会重新计算上传图片哈希并校验。异常会跳过当前答卷并记录原因，连续 3 次失败后暂停。

开发运行：`npm run electron:dev`

生成 Windows x64 安装包：`npm run package:win`

真实改卷网站接入时，只需替换 `electron/targetPreload.ts` 中的站点适配逻辑，评分模板、模型调用和本地历史数据不需要改动。

## 首版流程

1. 在“系统设置”配置 OpenAI 兼容的 `/chat/completions` 服务、人工复核阈值和教师模型推理强度。
2. 上传或粘贴题目、参考答案与评分标准。
3. 由文本模型生成结构化评分规则草稿。
4. 人工检查后锁定评分标准版本。
5. 上传学生作答图片并开始批改。
6. 视觉直批模式把题目文字、评分标准 JSON、题目图片、参考答案图片和学生答卷原图放入一次核心教师模型批改调用；不再先执行独立的完整卷面 OCR。模型只返回支持判分的最小证据片段，不生成整页转录。
7. 教师模型在同一结构化响应中对每个小问给出 `correct`、`incorrect`、`missing` 或 `uncertain` 权威结论，并对每个评分点给出 `satisfied`、`not_satisfied`、`not_present` 或 `unreadable` 审验结论。
8. 后端校验所有小问、评分点和证据引用，重新计算总分，不直接采用模型返回的总分；教师模型判定为 `correct` 的小问直接满分，过程审验仍完整执行和展示。
9. 系统累计整卷因 `unreadable` 实际未获得的分值，达到教师在系统设置中配置的阈值时才进入人工复核，默认阈值为 2 分。
10. 最终答案是否符合参考答案只由教师模型判断，本地表达式等价规则不再生成冲突、改变结论或触发复核。
11. 教师评语随批改结构在同一次模型调用中返回；后端在确定性计分后重新绑定失分点、证据引用和复核事项，评语缺失时使用本地降级评语，绝不改分。
12. 查看逐卷报告、教师判定依据、原图证据、过程审验状态、教师评语、本次复核阈值、执行数据和待复核原因。

“系统设置”中的“学生答卷批改方式”默认是“视觉直批（推荐）”。选择“先提取卷面证据，再分步评分”可以保留三次调用的兼容流程，适合模型暂时不支持一次性多模态结构化输出的服务。视觉直批模式下，锁定模板的题目图和参考答案图会随每份新答卷发送；历史重判会从本地模板重新读取这些图片。

评分标准锁定时会自动保存为本机模板；学生答卷完成批改后会把原图和结果写入对应模板的历史记录。通过“历史记录”可以重新打开场景、继续批改或用当前教师判定流程重新批改旧结果。重判会新增版本并记录 `previousResultId`，不会覆盖旧结果。通过“运行日志”可以查看视觉直批、兼容提取、教师评语、复核阈值聚合、规则计分和保存步骤。每次模型调用还会显示实际发送的 System Prompt、User Prompt、图像摘要、响应格式和模型原始 HTTP 返回。

计分器的系统不变量是：新批改结果始终是单一确定分值，不生成自动评分区间。只有清晰有效证据支持的 `satisfied` 评分点才能得分；`not_satisfied`、`not_present` 和 `unreadable` 当前均为 0 分。人工复核是独立工作流状态，不会提高 `maximumPossibleScore`。教师模型判定正确的最终答案是该小问的唯一权威结论，直接保持满分；过程评分点仍全部审验和展示，但不能降低该小问得分。最终答案错误、缺失或无法确认时，才按过程评分点确定固定分值。

页面使用 KaTeX 确定性渲染题目、评分标准和卷面转录中的 LaTeX，不再调用额外模型规整展示文本。模型结构化输出采用安全公式协议：JSON 中的 LaTeX 反斜杠使用 `[[LATEX_BS]]` 传输，服务端在完整 JSON 校验后恢复；混合正文中的行内公式使用 `$...$`，独立公式使用 `$$...$$`。前端用状态机生成不可拆分的文本/公式块，不按换行、逗号或中文标点切开公式。无法通过 KaTeX 校验的内容保留原文并显示回退提示。

没有模型密钥时可点击“载入演示批次”，直接查看完整工作流和报告界面。

## OpenAI 兼容约定

- `POST {baseUrl}/chat/completions`
- `Authorization: Bearer {apiKey}`
- 图片使用 `messages[].content[].image_url`
- 系统设置中保存的 Base URL、API Key、文本/多模态模型和调用参数是全局唯一配置；连接测试会先保存当前表单，再使用同一配置发起请求
- 多模态连接测试使用标准 `128x128` RGB PNG，避免部分供应商拒绝 `1x1` 灰度透明图片
- 视觉直批使用一次 `direct_vision_grading` 结构化响应，同时返回判分结果与教师评语；图片顺序为题目、参考答案、学生答卷
- 结构化输出按 `json_schema`、`json_object`、纯 JSON 顺序降级
- HTTP 200 但响应不符合业务 JSON 契约时同样视为本次模式失败，并继续执行结构化输出降级
- 教师模型推理强度在选择低、中或高时，会作为 `reasoning_effort` 传给最终答案判定和过程审验调用；服务端不支持该参数时应保持“默认”
- 每个结构化模型调用都会附加安全公式协议；直接出现在 JSON 字符串中的单反斜杠会被拒绝
- `finish_reason=length` 的响应视为已截断并整次作废，不从残缺文本中截取局部 JSON

API Key 由后端使用 AES-256-GCM 加密保存在 `.data/`，不会返回浏览器或写入 Git。

模板、题图、学生答卷和批改历史也保存在本机 `.data/`。运行日志保存在当前服务进程中，会记录完整文本 Prompt 和模型原始返回，但不记录 API Key 或图片 Base64；图片只记录类型、字节数和 SHA-256 摘要。
