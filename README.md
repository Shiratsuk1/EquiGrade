# 衡准 · 物理评分台

高中物理手写作答辅助批改首版。系统采用多模态证据提取、教师模型最终答案判定、全量过程审验、教师评语、本地审计和风险复核的分层流程。

## 启动

```powershell
npm install
npm run dev
```

前端默认运行在 `http://localhost:5173`，API 默认运行在 `http://localhost:8787`。

## 首版流程

1. 在“模型服务”配置 OpenAI 兼容的 `/chat/completions` 服务。
2. 上传或粘贴题目、参考答案与评分标准。
3. 由文本模型生成结构化评分规则草稿。
4. 人工检查后锁定评分标准版本。
5. 上传学生作答图片并开始批改。
6. 多模态模型先忠实提取卷面证据。
7. 独立教师模型结合原图、转录和锁定标准，对每个小问给出 `correct`、`incorrect`、`missing` 或 `uncertain` 权威结论。
8. 无论最终答案是否正确，所有小问都会调用过程审验模型逐点检查。
9. 只有高置信度且有有效卷面证据的 `correct` 小问直接满分；过程审验仍展示，过程问题和证据不足进入人工复核。
10. `incorrect` 或 `missing` 小问按评分标准计分；`insufficient_evidence` 评分点不计入已确认得分，保留为待复核分值并进入人工复核。
11. 本地等价引擎只输出审计信号，不能覆盖教师模型结论或扣分。
12. 计分完成后由教师模型生成结构化评语；评语调用失败时使用后端降级评语，绝不改分。
13. 查看逐卷报告、教师判定依据、过程审验状态、教师评语、审计冲突、执行数据和待复核原因。

评分标准锁定时会自动保存为本机模板；学生答卷完成批改后会把原图和结果写入对应模板的历史记录。通过“历史记录”可以重新打开场景、继续批改或用当前教师判定流程重新批改旧结果。重判会新增版本并记录 `previousResultId`，不会覆盖旧结果。通过“运行日志”可以查看证据提取、教师判定、全量过程审验、教师评语、本地审计、规则计分和保存步骤。

计分器的系统不变量是：教师模型对某小问返回高置信度且有有效卷面证据的 `correct` 时，该小问得满分，但过程点仍然审验并保存 `satisfied`、`not_satisfied` 或 `insufficient_evidence` 结论；证据不足的评分点不计入已确认得分，只计入待复核上限。低置信度、无效证据或本地等价审计冲突都会进入人工复核。旧评分标准中的 `finalAnswerPolicy` 不能改变这一结果。

页面使用 KaTeX 渲染题目、评分标准和卷面转录中的 LaTeX。一个字段包含多个 `$...$` 片段时会分别渲染，无法解析的内容保留原文并显示回退提示。

没有模型密钥时可点击“载入演示批次”，直接查看完整工作流和报告界面。

## OpenAI 兼容约定

- `POST {baseUrl}/chat/completions`
- `Authorization: Bearer {apiKey}`
- 图片使用 `messages[].content[].image_url`
- 结构化输出按 `json_schema`、`json_object`、纯 JSON 顺序降级

API Key 由后端使用 AES-256-GCM 加密保存在 `.data/`，不会返回浏览器或写入 Git。

模板、题图、学生答卷和批改历史也保存在本机 `.data/`。运行日志不记录 API Key、图片 Base64 或完整敏感请求正文。
